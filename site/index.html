One provider, the formats people actually use.

The Configure page keeps Wallpaper Engine properties separate from Dcent's desktop behavior. Selection, output ownership, and async preparation are tied to one immutable generation so stale work cannot apply the wrong wallpaper.

01

Live native scenes

CaptSilver's maintained SceneViewer renders particles, effects, scripts, video textures, project properties, and audio response in-process after isolated preflight.

02

Wallpaper Engine-compatible web runtime

Project properties, selectable directories, clickable controls, one reference viewport, and wallpaperRegisterAudioListener() support.

03

Real multi-screen behavior

Target one output, mirror the complete wallpaper, or span a synchronized canvas across mixed-DPI displays using KDE's real output identities.

04

No-flicker replacement

The active backend stays visible until its replacement reports usable content. Failed or slow candidates cannot intentionally expose an empty loader.

Source installation

Install the Plasma package. Keep ownership where it belongs.

DcentWallpapers requires KDE Plasma 6, Qt 6 WebEngine, Python 3, and the maintained CaptSilver native QML module. Fedora and Nobara are the currently tested distributions.

terminal
$ git clone https://github.com/dcenhance/dcent-wallpaper-linux.git
$ cd dcent-wallpaper-linux
$ kpackagetool6 --type Plasma/Wallpaper --install ./plasma-plugin
$ systemctl --user restart plasma-plasmashell.service
